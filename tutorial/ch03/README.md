# ch03. 연산자와 비트 폭 규칙

## 1. 학습 도달 목표

본 챕터는 HW02 과제와 직접 직결된다. HW02는 32비트 RV32 ALU를 설계하고 `zero`, `carry`, `overflow` 플래그를 정밀하게 추출하는 과제이며, 그 정확성은 본 챕터에서 다루는 비트 폭 확장 규칙과 부호 해석 원리에 기반한다.

Verilog HDL에서 가장 빈번히 발생하는 잠재 결함은 비트 폭 처리 오류다. 컴파일러 경고 없이 상위 비트가 절단되어 값이 왜곡되는 문제를 방지하기 위해 표준 연산 규칙을 완벽히 이해한다.

본 챕터의 6대 학습 핵심:

1. 하드웨어 연산자 분류 및 연산자 우선순위 체계
2. 수식의 연산 비트 폭을 결정하는 5대 문맥 규칙
3. 동일 비트 패턴의 Signed / Unsigned 2대 정수 해석 체계
4. 3종 시프트 연산자(`<<`, `>>`, `>>>`)와 `$signed` 결합 규칙
5. 4대 ALU 상태 플래그(`zero`, `negative`, `carry`, `overflow`)의 수학적 도출
6. 연산자 우선순위 혼동 및 부호 없는 비교 연산의 함정

## 2. 하드웨어 연산자 분류

[`ex01_operators.v`](ex01_operators.v)로 연산자 유형별 출력을 확인한다.

```bash
make test
```

`a = 4'b1100` (12), `b = 4'b0101` (5) 기준 실행 결과:

```text
--- 산술 연산자. 결과는 값이다 ---
a + b  = 0001
a - b  = 0111
a * b  = 1100
a / b  = 0010  정수 나눗셈이다
a % b  = 0010  나머지다
--- 비트 연산자. 비트마다 독립으로 계산한다 ---
~a     = 0011
a & b  = 0100
a | b  = 1101
a ^ b  = 1001
--- 논리 연산자. 결과는 1비트다 ---
!a         = 0  a가 0인지 판단한다
!zero_value= 1
a && b     = 1  둘 다 0이 아니면 1이다
a || b     = 1
zero_value && b = 0
--- 비트 연산자와 논리 연산자를 혼동하면 결과가 달라진다 ---
a & b  = 0100  비트마다 AND
a && b = 1  값이 0인지로 판단
--- reduction 연산자. 벡터 하나를 1비트로 줄인다 ---
&a     = 0  모든 비트가 1인지
|a     = 1  하나라도 1인지
^a     = 0  1인 비트가 홀수 개인지
~|a    = 0  모든 비트가 0인지
~|zero_value = 1
```

### 연산자 분류 체계

| 연산자 범주 | 연산 기호 | 연산 결과 비트 폭 | 주요 특징 및 하드웨어적 의미 |
|---|---|---|---|
| 산술 연산자 | `+`, `-`, `*` | 좌변/문맥 비트 폭에 따름 | 하드웨어 덧셈기, 뺄셈기, 곱셈기 매핑 |
| 비트 연산자 | `~`, `&`, `\|`, `^`, `~^` | 피연산자 폭과 동일 | 비트 단위 병렬 논리 게이트 매핑 |
| 논리 연산자 | `!`, `&&`, `\|\|` | 1비트 불리언 | 참(`1`), 거짓(`0`) 판정 조건문 매핑 |
| Reduction 연산자 | `&`, `~&`, `\|`, `~\|`, `^`, `~^` | 1비트 스칼라 | N비트 벡터를 단일 비트로 집약 (예: Zero 검출) |
| 관계 연산자 | `>`, `<`, `>=`, `<=` | 1비트 | Signed/Unsigned 대소 비교 회로 매핑 |
| 등가 연산자 | `==`, `!=` | 1비트 | 하드웨어 일치 여부 비교 회로 매핑 |
| 4치 항등 연산자 | `===`, `!==` | 1비트 | `x`, `z`를 포함한 완전 일치 비교 (Testbench 전용) |
| 시프트 연산자 | `<<`, `>>`, `>>>` | 좌변 피연산자 폭과 동일 | 배럴 시프터(Barrel Shifter) 매핑 |
| 조건 삼항 연산자 | `? :` | 문맥 비트 폭에 따름 | 2:1 멀티플렉서 매핑 |
| 비트 결합/복제 | `{}`, `{N{}}` | 부분 비트 폭의 합산 | 도선 재배치 및 부호 확장 회로 |

### Reduction NOR 기반의 Zero 플래그 도출

결과의 32비트가 모두 `0`인지 판정할 때 Reduction NOR(`~|`)를 적용한다.

```verilog
assign zero = ~|result;      // 32개 비트가 모두 0일 때 1'b1 생성
```

## 3. 5대 비트 폭 확장 규칙

[`ex02_width_rules.v`](ex02_width_rules.v) 실행 결과로 5대 규칙을 분석한다.

```text
a = f (15), b = 1 (1)
--- 규칙 1. 좌변 폭이 연산 폭을 정한다 ---
4비트에 담으면  a + b = 0000 (0)  자리올림이 사라진다
5비트에 담으면  a + b = 10000 (16)  자리올림이 남는다
--- 규칙 2. 자리올림은 결과 폭을 넓혀 얻는다 ---
wide_result[4] = 1  이것이 carry다
--- 규칙 3. 중간 표현식의 폭도 문맥이 정한다 ---
(a + b) >> 4 를 1비트에 담으면 = 0
({1'b0,a} + {1'b0,b}) >> 4  = 1  이 방식이 확실하다
--- 규칙 4. 폭 없는 상수는 32비트로 확장된다 ---
a + 1 == 16   -> 1  상수 1이 32비트이므로 폭을 유지한다
a + 4'b1 == 0 -> 1  4'b1은 4비트이므로 4비트로 계산된다
--- 규칙 5. 부호 없는 뺄셈은 폭 안에서 순환한다 ---
4비트에서 2 - 7 = 1011 (11)  기대한 -5 대신 순환한 값이 남는다
5비트에서 2 - 7 = 11011 (27)  폭을 넓혀도 부호 없이 순환한다
$signed를 붙이면  2 - 7 = 11011 (-5)  부호가 유지된다
```

### 규칙 1: 문맥 기반 연산 폭 결정 (Context-Determined Width)

Verilog는 수식을 계산할 때 좌변 신호의 비트 폭과 우변 피연산자들의 비트 폭 중 최댓값을 문맥 폭(Context Width)으로 설정하고 연산을 수행한다.

```verilog
reg [3:0] a, b;
reg [3:0] narrow_sum;
reg [4:0] wide_sum;

narrow_sum = a + b;   // 4비트 문맥: 4비트 덧셈 후 최상위 캐리 유실 (15 + 1 = 0)
wide_sum   = a + b;   // 5비트 문맥: 5비트 덧셈 수행, 캐리 보존 (15 + 1 = 16)
```

### 규칙 2: 비트 폭 확장을 통한 Carry 보존

Carry 비트를 안전하게 추출하기 위해 피연산자에 `1'b0`을 명시적으로 결합하여 5비트(또는 33비트) 문맥을 강제한다.

```verilog
wire [32:0] wide_sum = {1'b0, a} + {1'b0, b};   // 32비트 a, b 기준
wire [31:0] sum      = wide_sum[31:0];
wire        carry    = wide_sum[32];
```

### 규칙 3: 중간 표현식의 문맥 전파

수식 내부의 연산도 전체 문맥 폭의 영향을 받는다. 따라서 복합 수식에서는 중간 신호를 명시적 폭과 함께 분할 선언하여 의도치 않은 비트 절단을 방지한다.

### 규칙 4: 무지정 정수 상수의 32비트 기본 배정

비트 폭을 명시하지 않은 정수 상수(`1`)는 32비트 상수로 간주되어 전체 수식의 문맥 폭을 32비트로 확장한다. 비트 폭을 명시한 상수(`4'b0001`)를 사용하여 의도한 비트 폭을 엄격히 통제한다.

### 규칙 5: 2의 보수 모듈로 순환 (Modulo Wrap-Around)

부호 없는 4비트 뺄셈 `2 - 7` 수행 시 $2^4 = 16$ 모듈로 연산이 적용되어 `11` (`4'b1011`)로 순환한다. 동일 비트열에 `$signed`를 적용할 때 2의 보수 정수 `-5`로 정확히 해석된다.

## 4. Signed / Unsigned 부호 해석 체계

[`ex03_signed.v`](ex03_signed.v) 실행 결과:

```text
--- 선언이 해석을 정한다 ---
4'b1111을 부호 없이 읽으면 15
4'b1111을 부호 있게 읽으면 -1
--- $signed와 $unsigned로 해석을 바꾼다 ---
u          = 1010 -> 10
$signed(u) = 1010 -> -6
s            = 1010 -> -6
$unsigned(s) = 1010 -> 10
--- 비교 결과가 해석에 따라 갈라진다 ---
u > 4'd0 -> 1  15 > 0 이므로 참이다
s > 4'sd0 -> 0  -1 > 0 이므로 거짓이다
--- 혼합 규칙. 부호 없는 값이 하나라도 있으면 전체가 부호 없이 계산된다 ---
s        = 1111 (-1)
s < 4'sd1 -> 1  부호 있는 비교
s < u     -> 0  u가 부호 없으므로 s도 부호 없이 읽힌다
$signed(s) < $signed(u) -> 1  양쪽에 붙이면 부호 비교가 된다
```

### 부호 혼합 연산 규칙 (Mixed-Sign Expression Rule)

표현식 내에 부호 없는(Unsigned) 피연산자가 단 하나라도 존재하면 수식 전체가 Unsigned 연산으로 강제 형변환된다. 따라서 부호 있는 비교를 수행할 때는 비교 대상 **양측 피연산자 모두에 `$signed`를 명시**한다.

```verilog
// Signed Less-Than (SLT) 올바른 구현식
assign slt_result = ($signed(a) < $signed(b) ? 1'b1 : 1'b0);
```

## 5. 3종 시프트 연산자

[`ex04_shift.v`](ex04_shift.v)는 RV32I의 `sll`, `srl`, `sra` 하드웨어 연산을 실증한다.

```verilog
assign sll_result = a << shamt;              // 좌측 논리 시프트 (SLL)
assign srl_result = a >> shamt;              // 우측 논리 시프트 (SRL, 0 채움)
assign sra_result = $signed(a) >>> shamt;    // 우측 산술 시프트 (SRA, 부호 비트 복제 채움)
```

산술 우측 시프트(`>>>`)는 좌변 피연산자가 `$signed`로 캐스팅된 경우에만 최상위 부호 비트를 상위 빈자리에 복제한다. Unsigned 신호에 `>>>`를 적용하면 논리 시프트(`>>`)와 동일하게 `0`이 채워진다.

RV32I 32비트 프로세서에서 시프트 양(Shift Amount)은 하위 5비트(`b[4:0]`, 범위 0~31)를 취하여 연산에 사용한다.

## 6. 4대 ALU 상태 플래그 도출 원리

[`ex05_flags.v`](ex05_flags.v)는 4비트 덧셈으로 플래그 생성 논리를 검증한다.

```verilog
wire [4:0] wide_sum = {1'b0, a} + {1'b0, b};

assign sum      = wide_sum[3:0];
assign carry    = wide_sum[4];
assign zero     = ~|sum;
assign negative = sum[3];
assign overflow = (a[3] == b[3]) && (sum[3] != a[3]);
```

### 플래그별 하드웨어 판정 수식

1. Zero 플래그 (`zero`): 연산 결과의 32개 비트가 모두 `0`인지 판정 (`~|sum`)
2. Negative 플래그 (`negative`): 연산 결과의 최상위 부호 비트 확인 (`sum[31]`)
3. Carry 플래그 (`carry`): Unsigned 덧셈 결과가 32비트 범위를 초과하여 발생한 최상위 자리올림 비트 (`wide_sum[32]`)
4. Signed Overflow 플래그 (`overflow`): Signed 2의 보수 덧셈에서 두 피연산자의 부호가 동일하고 결과의 부호가 피연산자 부호와 상이할 때 발생 (`(a[31] == b[31]) && (sum[31] != a[31])`)

### Carry와 Overflow의 독립성

| 피연산자 A | 피연산자 B | Unsigned 덧셈 판정 | Signed 2의 보수 덧셈 판정 | `carry` | `overflow` |
|---|---|---|---|---:|---:|
| `4'b1111` (15) | `4'b0001` (1) | $15+1=16$ (32비트 초과) | $-1+1=0$ (정상 범위) | 1 | 0 |
| `4'b0111` (7) | `4'b0001` (1) | $7+1=8$ (정상 범위) | $7+1=8$ (Signed 최대 7 초과) | 0 | 1 |
| `4'b1000` (8) | `4'b1000` (8) | $8+8=16$ (32비트 초과) | $-8+(-8)=-16$ (최소 -8 초과) | 1 | 1 |
| `4'b0011` (3) | `4'b0010` (2) | $3+2=5$ (정상 범위) | $3+2=5$ (정상 범위) | 0 | 0 |

Carry와 Overflow는 상호 독립적인 하드웨어 상태 플래그다.

## 7. 연산자 우선순위 및 비교 함정

1. 등가 연산자 우선순위 함정: `a & b == c`는 `a & (b == c)`로 평가된다. 의도한 연산 수행을 위해 `(a & b) == c`처럼 명시적 괄호를 사용한다.
2. 부호 없는 비교 연산: `32'hffff_ffff`와 `32'h0000_0001` 비교 시 Unsigned 비교(`sltu`)는 $4294967295 > 1$로 거짓(`0`)을 반환하고, Signed 비교(`slt`)는 $-1 < 1$로 참(`1`)을 반환한다.
